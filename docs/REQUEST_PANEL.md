# Панель создания заявок

Для защищённой сети ЦОД по решению пользователя и эксперта вход по логину
и паролю отсутствует. PANEL_PASSWORD больше не используется и не создаётся.
Старое значение в .env можно удалить, на запуск оно не влияет.

После обновления проекта:

    bash scripts/deploy-panel.sh

Панель: http://SERVER_IP:8082/. Карта через панель: /map.
PANEL_PORT и PANEL_BIND переопределяются в .env; по умолчанию 0.0.0.0:8082.
Отдельный профиль Compose panel запускает форму, основной API остаётся прежним.

Выберите адрес, тип работ, дату и начало желаемого двухчасового слота.
Форма передаёт заявку Fastify API и показывает фактическое назначение.
Демонстрационные справочники можно загрузить кнопкой только в пустую БД:
при существующих сотрудниках/днях загрузка отклоняется с 409.

Адреса взяты из data/, произвольные адреса вне матрицы не поддерживаются.
Потребность тестовой заявки: ONT для PON и ROUTER, контрольный срок — 3 дня.
Это параметры генератора для проверки, не универсальные нормативы.
Сеть и разграничение доступа обеспечиваются инфраструктурой размещения.

## Исправление обновления страницы

Панель переведена с однопоточного HTTPServer на ThreadingHTTPServer.
Пустое предварительно открытое соединение браузера и длительный запрос
создания заявки больше не занимают единственный обработчик. У соединений
установлен socket timeout 20 с. Проверка scripts/check_panel_connections.py
открывает пустое TCP-соединение и параллельно запрашивает страницу 8 раз;
локально в Docker прошла за 0,28 с. Проверка не меняет данные.
Если после обновления сервер не отвечает, проверить docker compose logs
request-panel и доступность 127.0.0.1:8082 с самого сервера: сетевую причину
по одному внешнему тайм-ауту исключить нельзя.

## HTTP-браузеры и позднее время заявки

web/uuid.js создаёт идентификаторы событий и на обычном HTTP, где
crypto.randomUUID может отсутствовать. Функция не используется для секретов.
Тест uuid.test.mjs проверяет native, getRandomValues и резервный вариант.

Поиск результата новой заявки в панели ограничен исходным и принимающим
днём из transferred_orders, вместо обхода всех календарных дней.
Backend-вызовы панели ограничены 35 с, клиент ожидает до 60 с. При тайм-ауте
не следует слепо повторять заявку: она могла сохраниться, сначала проверить карту.
HTML панели отдаётся с Cache-Control: no-store.

Регрессия 21:00: в локальном Docker на полном наборе справочников новая
REPAIR-заявка с желаемым слотом 18 ноября 21:00 назначена на 19 ноября
09:05:52–10:05:52, HTTP-ответ получен за 0,32 с. Это проверка конкретного
сценария, не гарантия времени для всех сочетаний заявок. 18 Python-тестов прошли.

## Исправление контрольного срока

Новые заявки панели получают deadline по work_types.csv: HOURS — часы от
registered_at (REPAIR 24/12, DEGRADATION 48); WORKING_DAYS — заданное число
будних дней от регистрации с сохранением времени (допущение Пн–Пт без
праздников); SLOT — конец выбранного слота. Прежняя фиксированная прибавка
3 дней отменена. Входные deadline официального API не пересчитываются.
registered_at берётся из модельного времени дня, не из часов телефона.
Существующие заявки автоматически не исправляются, чтобы не переписать историю.
В карточке поле называется «Контрольный срок»; это не обещанное время визита.

## Счётчики и выбранный сотрудник

Панель расширена до «Режима отладки»: события, управление модельным временем
и карта с автообновлением. Подробный протокол, ограничения автоматизации и
пошаговый показ эксперту: [DEBUG_MODE.md](DEBUG_MODE.md).

Панель показывает статистику выбранной даты: всего нарядов в её активном
пуле, назначено, не назначено, ожидают расчёта, перенесено на другие дни,
активные риски. До построения плана наряды считаются ожидающими расчёта,
а не ошибочно назначенными. При переносе в другой день наряд входит в
суточный пул принимающей даты; исходная показывает его отдельно как перенос.
Карта также показывает явные суточные счётчики независимо от фильтров поиска.

В форме есть «Сотрудник»: автоматический выбор или тестовое закрепление.
Оно сохраняется в _test_staff_id и действует при подборе другого времени/дня.
Fastify проверяет существование, профиль, технологию, высотный допуск и
вместимость оборудования. Нельзя закрепить несовместимого мастера, чтобы
искусственно нарушить правила. Длительность, дорога, обед и смена сохраняются.
Это дополнительный тестовый параметр, не изменение официального Order.

Для риска создать два последовательных наряда одному мастеру и в карте
передать VISIT_DELAYED по первому визиту. Если следующий уже перенесён,
предупреждение закрывается: включить историю «Показать закрытые».
Нулевой счётчик активных рисков не означает отсутствия истории предупреждений.

Форма фильтрует типы работ по адресу: инсталляции МКД — по технологии
PON/FTTB, работы частного сектора — по типу дома и наличию воздушной линии.
Список сотрудников учитывает профиль, технологию, высотный допуск и
вместимость комплекта для создаваемой заявки. При изменении адреса или работ
несовместимый выбранный мастер сбрасывается на автоматический выбор.
Это предварительная проверка квалификации, а не свободного времени:
доступность, маршрут и обед по-прежнему рассчитывает планировщик.
Если подходящих мастеров нет, форма объясняет причину и блокирует отправку.
Прямой запрос панели с несовместимыми работой и адресом получает HTTP 422
WORK_BUILDING_MISMATCH до создания дня. Fastify сохраняет независимую
проверку выбранного мастера и сообщает конкретную причину отказа по-русски.

Проверено на отдельном Docker-стенде: для B-00071 (МКД, FTTB) скрыты
INST_PRIVATE_VLS и ST-003 при инсталляции; прямой неверный запрос отклонён
с HTTP 422. Совместимая инсталляция назначена ST-029 на 18 ноября
09:30–10:30. Прошли 24 Python-, 12 JS- и 6 API-тестов; браузерный прогон
фильтров прошёл без ошибок JavaScript.

Проверено: unit-сценарий закрепления двух визитов, задержка и LATE_RISK;
HTTP-создание на выбранного ST-027 и статистика total=1, assigned=1,
unassigned=0. Панель с пустыми справочниками после их загрузки обновляет
страницу для заполнения списка сотрудников.
