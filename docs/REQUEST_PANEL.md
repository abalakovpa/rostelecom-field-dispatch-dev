# Панель создания заявок на сервере

Опциональный Docker Compose profile panel. Основное приложение продолжает
работать как раньше. После обновления исходников на сервере:

    bash scripts/deploy-panel.sh

Скрипт создаёт PANEL_PASSWORD в существующем .env, если настройки ещё нет,
и поднимает панель. Адрес http://SERVER_IP:8082/, пользователь admin.
Посмотреть пароль под root: grep '^PANEL_PASSWORD=' .env.
Не пересылать .env и не коммитить его. Нужен свободный порт 8082 и доступ
к нему по сети. PANEL_PORT и PANEL_BIND можно переопределить в .env.
Для локальной проверки PANEL_BIND=127.0.0.1.

Панель использует HTTP Basic Authentication и защиту записывающих запросов
от обычной межсайтовой формы. По HTTP пароль не шифруется: для реальных
данных нужен HTTPS через reverse proxy или SSH-туннель. Не использовать
этот пароль для других сервисов. Это панель тестовой проверки, не полноценная
система авторизации с ролями, аудитом пользователей и ограничением попыток.

Выбрать адрес, тип работы, дату и начало желаемого двухчасового слота.
Форма вызывает Fastify REST API; прямых SQL-записей нет. Возвращает фактические
дату, исполнителя, начало и конец. По ссылке /map открывается карта того же API,
а запросы карты проксируются через защищённую панель.

В пустой БД нажать «Загрузить демонстрационные справочники». Если уже есть
сотрудники или дни, панель возвращает 409, чтобы не стереть данные.
Адреса/нормативы в форме взяты из поставляемого data/. При загрузке другого
набора справочников форму нужно синхронизировать: не поддерживаются произвольные
адреса вне матрицы. Данные условные: deadline создаваемой заявки — через 3 дня,
потребность ONT для PON и ROUTER. Поддержка календаря и подбора не означает
гарантию выезда без квалифицированных сотрудников/оборудования.

Проверено локально: 401 без авторизации; форма/карта/JS 200 с паролем;
409 при попытке повторной загрузки справочников; создание заявки через API
и получение назначения. Серверный запуск выполняется пользователем отдельно.
