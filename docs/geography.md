# География набора: Орджоникидзевский район

В исходном генераторе координаты были искусственными смещениями и могли
попадать в воду. Генератор больше не допускает такой запасной вариант.

Исправленная версия содержит 80 реальных адресных жилых домов и 5 различных
зданий под условные СЦ в Орджоникидзевском районе Екатеринбурга. Граница района:
https://www.openstreetmap.org/relation/5819002 . Источник адресов и контуров —
официальный API https://api.openstreetmap.org/api/0.6/ ; исходники закэшированы.
© OpenStreetMap contributors, ODbL: https://www.openstreetmap.org/copyright .

Для каждого здания:

1. Требуются `building`, `addr:street`, `addr:housenumber` и замкнутый контур.
2. Тип `MKD`/`PRIVATE` соответствует тегу здания OSM.
3. Точка выбирается на внутреннем отрезке пересечения полигона со сканирующей
   линией. Проверка ray casting подтверждает, что она внутри контура здания.
4. Проверяется принадлежность точки внешнему контуру границы района OSM.

Выбранная граница не содержит внутренних колец; источник сохранён для сверки.
Узлы доступа условно расположены по адресу одного из обслуживаемых домов.
Существование настоящих СЦ/узлов связи по этим адресам не утверждается.
Синтетический признак ВЛС не получен из OSM и не описывает реальное подключение.

Повторная подготовка:

```powershell
$env:OSM_DIRECT='1'
.\.venv\Scripts\python.exe scripts/fetch_real_buildings.py
.\.venv\Scripts\python.exe scripts/generate_data.py --fetch-osrm
.\.venv\Scripts\python.exe scripts/build_seed_sql.py
```

Без `--fetch-osrm` используется кэш; при несовпадении координат генератор
останавливается. Матрица `ekb-ordzhonikidzevsky-osm-v3`
рассчитана заново, диагональ нулевая; добавлены условные
180 секунд на парковку/подход. Координаты дома не подменяются привязкой к дороге.

Изменения общей БД согласуются с серверным разработчиком и выполняются его
миграциями. Старый скрипт `demo/scripts/update_real_geography.py` относится только
к отдельной базе прототипа и не предназначен для командной PostgreSQL.
Источники и удалённые из набора сырые кэши — `geodata_sources.md`.

## Пространственная выборка

Дома выбираются до СЦ, без поиска ближайших домов к центрам. В каждом типе жилья
используется случайная выборка из занятых ячеек размером 600 м: вес пропорционален
корню числа адресных зданий с уменьшением веса уже представленных ячеек.
Координаты остаются внутри настоящих зданий; регулярной сетки маркеров нет.
Для одного типа жилья минимальное расстояние 100 м, не более 5 выбранных домов
на одной улице. Между разными типами общая граница 100 м не навязывается.
Пять СЦ выбираются после домов независимо, в других зданиях, с расстоянием
между СЦ минимум 900 м. Seed фиксирован для воспроизводимости.

В текущем наборе 80 домов на 51 улице; только 18 домов находятся в пределах
500 м от любого СЦ, медиана расстояния до ближайшего СЦ — около 755 м.
Это контроль распределения по прямой, а не дорожное время для солвера.
Отчёт — `data/provenance/spatial_distribution.json`.
Образец относится к адресным жилым зданиям доступного извлечения OSM внутри
района; равномерность по лесам/промзонам не требуется, а реальная плотность
частных домов и МКД различается. Телефонная топология по-прежнему синтетическая.
