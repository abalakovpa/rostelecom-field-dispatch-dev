# Синтетические данные и допущения

По сообщению пользователя организаторы разрешили: «данные можете придумать сами, обусловленные».
Для разработки и демонстрации используем синтетические данные с обоснованием.
Набор данных пока не создан; перечисленное ниже — требования к его подготовке.

- Явно указать город, дату смены, часовой пояс и единицы измерения.
- Описать число сотрудников и нарядов, профили, технологии, высотные допуски,
  смены, обед, сервисные центры и остатки оборудования.
- Обосновать длительности работ, временные слоты и контрольные сроки.
- Указать источник или метод расчёта времени переездов. Приближённую матрицу
  явно обозначить как синтетическую, а не как реальные дорожные маршруты.
- Подготовить обычные и пограничные сценарии: несовместимый допуск,
  нехватка оборудования, риск опоздания, задержка, отмена, недоступность
  сотрудника, групповые неисправности и сохранение выполненных визитов.
- Для нагрузочной проверки подготовить 350–450 нарядов за день.
- Зафиксировать seed генератора для воспроизводимости.

Разрешение на синтетические данные не заменяет требования кейса.
Порог группировки и другие неуточнённые правила обозначать как допущения.
При отсутствии api_spec.yaml внешний контракт остаётся временным.

Решение работает через серверное API и интерфейс диспетчера.
Боты и мессенджеры не входят в состав проекта.
