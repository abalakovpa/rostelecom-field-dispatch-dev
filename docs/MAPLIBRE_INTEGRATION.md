## Защита существующей БД

Обычное обновление исходников/контейнеров не загружает новую географию
и не очищает заявки. Панель теперь читает каталог из PostgreSQL через
/api/ui/catalog, поэтому старые справочники остаются согласованными с
прежней матрицей и планами. Можно обновить интерфейс без сброса данных.

Для перехода именно на новую географию:

    git pull --ff-only
    bash scripts/deploy-panel.sh

Затем, только если согласован сброс тестовых дней:

    bash scripts/update-city-data.sh --replace-demo-data

Команда временно останавливает работавшие API/панель, сохраняет полный
pg_dump в backups/, проверяет читаемость архива, валидирует новые данные
и заменяет reference+matrix+days в одной SQL-транзакции. Старые дни/планы
очищаются. При выходе скрипта запускаются ранее работавшие сервисы.
При ошибке валидации/транзакции состояние не заменяется; дамп остаётся.
backups/ исключён из Git, доступ к файлам ограничен umask 077.

Это не миграция координат существующих визитов. Для сохранения старой
истории используется полный дамп. Восстановление выполнять в отдельную
БД для проверки, затем согласованно переключать приложение. Не запускать
pg_restore поверх действующей БД без остановки записи и плана восстановления.
