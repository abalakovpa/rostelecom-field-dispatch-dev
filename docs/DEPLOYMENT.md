# Локальная подготовка

Состав: PostgreSQL 16, одноразовые транзакционные SQL-миграции, Fastify API.
БД и API публикуются только на localhost. Ботов нет.

## Запуск

Скопировать .env.example в .env и заменить CHANGE_ME на свой пароль.
Запустить Docker Engine (на Windows — Docker Desktop), затем:

    docker compose up --build -d
    docker compose ps

Проверить http://localhost:3000/health — 200 означает успешный SELECT 1.
При недоступной БД возвращается 503. Для pgAdmin: localhost, порт 5432,
база dispatch, пользователь dispatch, пароль из .env.

Миграции хранятся в db/migrations и применяются один раз перед запуском API.
Добавлять новые файлы, а не менять уже применённые. Данные сохраняются в
именованном томе pgdata; команда down -v удаляет их.

## Текущий объём

Схема содержит снимки состояния с версией, результаты планирования и журнал
событий. Предметные REST-маршруты, применение событий и вызов планировщика
ещё не реализованы. /health — единственный работающий endpoint.
Пример docs/examples/planner-contract.json перенесён из PR № 4 без изменений,
это временный внутренний контракт и синтетический пример, не готовый расчёт.
Замечания к нему: docs/PR4_REVIEW.md.

Следующий этап: согласовать контракт и транспорт с автором планировщика,
реализовать загрузку и валидацию снимка, сохранение результата с проверкой
версии, обработку событий и интеграционные проверки в PostgreSQL.
Нагрузочный набор и интерфейс ещё предстоит подготовить.

Публикация инфраструктуры выполняется отдельной веткой. Сервер пока не изменяется.

## Bash-развёртывание

На Ubuntu 24.04 или 26.04 из корня загруженного/клонированного репозитория:

    sudo bash scripts/deploy.sh --install-docker

Если Docker Engine и Compose v2 уже установлены:

    sudo bash scripts/deploy.sh

Скрипт создаёт .env со случайным паролем, если файла ещё нет, сохраняет
существующий .env, запускает миграции и ждёт готовности API. Секреты не печатает.
Для приватного репозитория клонирование выполняется отдельно через SSH-ключ
или GitHub-аутентификацию. Не записывать ключи/токены в скрипт или git.

Для подключения с ноутбука:

    ssh -N -L 15432:127.0.0.1:5432 -L 3000:127.0.0.1:3000 USER@SERVER

В pgAdmin: localhost:15432, база и пользователь dispatch; пароль находится
в серверном .env. API: http://localhost:3000/health.
Установщик не настраивает SSH, firewall или публичный HTTPS.
Полный запуск на чистом сервере пока не проверен.
