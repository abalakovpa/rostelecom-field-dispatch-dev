# Карта и API: запуск текущего этапа

Для этой рабочей копии используйте [api_loading.md](api_loading.md): собственная
база `dispatcher_next_20261114`, порт приложения 8083, миграции 001 и 002.
Настройки уже заполнены в `.env`; не направляйте загрузки в исходную `dispatcher`.

Сейчас приложение показывает данные из PostgreSQL: даты, СЦ, сотрудников и наряды
на карте Leaflet/OpenStreetMap. Есть поиск, фильтры технологий/профилей, карточки,
список команды и группировка нескольких нарядов в одном доме.
Кнопка «Рассчитать план» запускает OR-Tools с лимитом 30 секунд. Список показывает
назначения и начало визитов; выбор сотрудника загружает дорожный маршрут OSRM.
Алгоритм и ограничения описаны в `planner.md`. Ниже карты появился блок событий:
выберите тип, проверьте JSON-пример и нажмите «Применить событие». Появится новая
версия плана с сохранением начатых визитов. Подробности — `events.md`, открытый
вопрос о выбывшем сотруднике — `open_questions.md`.
Добавлены Гант, фильтры статусов, причины неназначения и панели предупреждений/ПГП;
см. `dispatcher.md`. Полная загрузка данных через API реализована — `api_loading.md`.

## С вашей PostgreSQL из pgAdmin

pgAdmin — клиент. Приложение подключается к тому же серверу PostgreSQL по host,
port, имени базы и пользователю. Устанавливать вторую БД через Docker не нужно.

1. В терминале PowerShell в корне проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

2. Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Если уже есть —
   отредактируйте его, не перезаписывайте существующие параметры.
3. В `.env` укажите подключение из свойств сервера pgAdmin:

```dotenv
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432
POSTGRES_DB=dispatcher_next_20261114
POSTGRES_USER=dispatcher_next_20261114
POSTGRES_PASSWORD=ваш_пароль
DATA_SOURCE=postgres
```

Пользователь `postgres` приведён как пример: используйте своего пользователя.
Пароль хранится локально в игнорируемом `.env`; не отправляйте его в чат и Git.
Просмотр карты читает данные; расчёт, события и PUT-загрузки записывают их в БД.

4. Запустите:

```powershell
.\scripts\start.ps1
```

Перед запуском сервер проверяет подключение и выводит количество СЦ, сотрудников,
нарядов и дней. Если на компьютере несколько установок PostgreSQL, используйте
порт из **Properties → Connection** того сервера pgAdmin, где заполнена база.
Отдельно проверить подключение, не запуская карту:

```powershell
.\.venv\Scripts\python.exe scripts/check_connection.py
```

Если PowerShell блокирует скрипты, менять системную политику не нужно:

```powershell
.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8083 --env-file .env
```

Откройте http://127.0.0.1:8083 . Остановка — Ctrl+C в терминале.
Если порт занят, используйте `-Port 8081` у скрипта либо `--port 8081` у uvicorn.

## Демо без подключения к БД

```powershell
.\scripts\start.ps1 -Demo
```

В этом режиме используются файлы `data/`, а интерфейс явно показывает «Демо».
При ошибке PostgreSQL автоматического переключения на файлы нет.
Для запуска без PowerShell-скрипта:

```powershell
$env:DATA_SOURCE = 'demo'
.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8083
```

Тайлы OSM и необязательный веб-шрифт требуют интернета. Leaflet 1.9.4 включён
локально с лицензией; при недоступности тайлов список и маркеры остаются доступны,
а карта показывает предупреждение. Атрибуция OpenStreetMap сохранена.
Координаты сотрудников не выдумываются: карточка команды показывает закреплённый СЦ.

## Docker Compose — отдельный вариант

```powershell
docker compose up --build -d
```

Создаёт собственную контейнерную PostgreSQL, отдельно от сервера, который вы
заполнили через pgAdmin. Если локальная БД занимает 5432, задайте в `.env`
`DOCKER_POSTGRES_PORT=5434`: внутри Compose API всё равно подключается к `db:5432`.
При пустом томе создаётся схема, но данные автоматически не импортируются.
Для импорта с локального компьютера (если контейнерная база ещё пустая):

```powershell
Get-Content -Raw -Encoding UTF8 db/seeds/001_generated_data.sql | docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## Текущие эндпоинты

| Путь | Назначение |
|---|---|
| `/` | Карта диспетчера |
| `/api/v1/health` | Проверка доступа к источнику и наличия схемы |
| `PUT /api/v1/reference` | Полная замена справочников и сброс загруженных дней |
| `PUT /api/v1/reference/travel-matrix` | Загрузка матрицы поездок |
| `PUT /api/v1/days/{date}` | Замена дня со сбросом его планов и событий |
| `/api/v1/days/{date}/plan` | Чтение существующего плана; `404`, если план не создан (по OpenAPI) |
| `POST /api/v1/days/{date}/plan` | Первоначальный расчёт и сохранение версии 1 |
| `POST /api/v1/days/{date}/events` | Событие и новая версия плана, повтор event_id идемпотентен |
| `/api/ui/days/{date}/routes/{staff_id}/geometry` | Дорожная геометрия выбранного маршрута |
| `/api/ui/bootstrap` | Даты, СЦ, сотрудники и типы работ для интерфейса |
| `/api/ui/days/{date}` | Рабочие наряды дня и сохранённый план без обучающего `fact` |
| `/docs` | Документация уже реализованных эндпоинтов |
| `/case-api.yaml` | Исходная полная спецификация организаторов |

`/api/ui/*` — дополнительные эндпоинты UI, разрешённые спецификацией.
Схема `/openapi.json`, которую создаёт FastAPI, описывает только текущую реализацию;
она не заменяет исходный `api_spec.yaml`. Все основные пути загрузки, планирования
и событий реализованы; скрытый прогон организаторов ещё не выполнялся.
Время интерфейса — модельное `now` из дня и зона `Asia/Yekaterinburg`, не часы компьютера.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Проверки API выполняются на явном файловом источнике; ошибки подключения PostgreSQL
проверяются отдельно. Доступ к вашей БД требует заполненного `.env`. Наличие карты
не означает готовность расчёта, перепланирования или всего API организаторов.
