# Открытые вопросы к организаторам

## Напомнить при финальной сверке: обед выбывшего сотрудника

Статус: **нужно уточнить у организаторов**. Пользователь просил сохранить этот
вопрос и напомнить о нём позже, при итоговой проверке соответствия кейсу.

OpenAPI H3 требует ровно один BREAK, если в маршруте есть визиты. Одновременно
STAFF_UNAVAILABLE запрещает остановки, начинающиеся в период недоступности.
Если сотрудник успел начать визит, ещё не обедал и выбыл до конца смены,
выполнить оба требования невозможно. Добавить обед задним числом нельзя из-за H10.

Нужно уточнить: распространяется ли H3 на маршрут сотрудника, выбывшего до конца
смены, и какое поведение ожидает валидатор в этом случае?

Согласованное текущее решение: **строгая проверка без исключения**. Возвращаем
409 `UNAVAILABILITY_BREAK_CONFLICT`, не сохраняем событие и не меняем время/план.
Это явно обозначенный неподдерживаемый противоречивый сценарий, а не подтверждение
полной обработки всех возможных входных событий. Не ослаблять H3 автоматически.
