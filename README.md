# Умная диспетчеризация выездных бригад

Командное решение кейса № 05 Ростелекома. Сервис распределяет наряды на подключение и ремонт, строит маршруты на смену и обновляет план при событиях.

Разработка, задачи и pull requests ведутся здесь. В [репозиторий для сдачи](https://github.com/abalakovpa/rostelecom-field-dispatch) переносим проверенную версию в формате, который требуют организаторы.

## Кто за что отвечает

| Модуль | Ответственность |
| --- | --- |
| Планировщик | Проверка ограничений, дневной план, пересчёт оставшихся визитов, причины неназначения и риски опоздания. |
| Сервер | REST API, загрузка данных, состояние смены, события, группировка подозрений на общую неисправность и Docker Compose. |
| Интерфейс | Карта маршрутов, диаграмма Ганта, списки нарядов и предупреждений, проверка сквозного сценария. |

## Первый сквозной сценарий

1. Сверить форматы с `api_spec.yaml` организаторов и согласовать интерфейс между сервером и планировщиком.
2. Добавить синтетический пример ответа API с маршрутом, рисковым и неназначенным визитами. Подключить интерфейс к примеру, пока разрабатывается планировщик.
3. Загрузить наряды, построить план, отправить событие о задержке и увидеть новый маршрут и предупреждение. Выполненные визиты должны сохраниться.
4. На 350–450 нарядах в день проверить ограничения и замерить время. На дневной план отводится до 5 минут, на ответ по событию до 10 секунд.

## Материалы и запуск

Организаторы разрешили самостоятельно подготовить синтетические данные с обоснованными допущениями. Готовим `staff.json`, `service_centers.json`, `access_nodes.json`, `work_types.csv`, `orders_train.json` и `events_example.json`; параметры и ограничения описываем в `docs/DATA_ASSUMPTIONS.md`. Формат внешнего API сверяем с `api_spec.yaml`, если организаторы его предоставят.

Репозиторий на этапе подготовки. По условию готовый сервис должен запускаться командой `docker compose up`. Общие правила работы описаны в [AGENTS.md](AGENTS.md).


Локальная инфраструктура и Bash-развёртывание: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Сейчас реализованы PostgreSQL, миграции и API /health; планировщик и предметные REST-маршруты ещё в разработке.

Официальный контракт организаторов: [api_spec.yaml](api_spec.yaml). [План перехода Fastify API](docs/API_IMPLEMENTATION.md) описывает отличия от внутреннего черновика и оставшиеся работы.
