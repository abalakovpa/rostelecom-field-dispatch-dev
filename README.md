# Умная диспетчеризация выездных бригад

Интегрированное решение кейса № 05: Fastify REST API, PostgreSQL 16,
Python-планировщик Павла и карта/Гант Михаила.

## Запуск

    docker compose up --build -d --wait

Интерфейс: http://127.0.0.1:8080/.
Готовность: http://127.0.0.1:8080/api/v1/health.

На Ubuntu 24.04/26.04 можно установить Docker и запустить сервисы:

    bash scripts/deploy.sh --install-docker

Для установки Docker нужны права root. Если Docker установлен:

    bash scripts/deploy.sh

Скрипт создаёт .env со случайным паролем БД. При прямом запуске Compose
без .env используется публичный пароль local-evaluation-only для локальной
оценки; для сервера задайте собственный POSTGRES_PASSWORD. Порты доступны
только на localhost; для доступа с ноутбука используйте SSH-туннель.

Исходные данные в data/ не загружаются автоматически. Официальные операции
описаны в api_spec.yaml. Проверочный сценарий scripts/check_integrated.py
загружает небольшие примеры и заменяет данные: запускать только на отдельном
тестовом экземпляре с явным --allow-reset.

## Что реализовано

Загрузка справочников, матрицы и дня; расчёт плана; события и модельное время;
версии, идемпотентность и транзакционное сохранение; карта и Гант;
автоматические переносы с резервированием следующих дней; прерывание работы,
возврат через СЦ и группы аварий с отдельными визитами.

Продуктовые уточнения для ручной проверки отличаются от исходного OpenAPI:
контрольный срок — показатель просрочки, а не запрет на позднее назначение;
группы с отдельными визитами хранятся в incident_groups; прерванная работа
перепланируется с сохранением истории. Исходная спецификация не изменена.
Безусловное назначение произвольной заявки не гарантируется: поиск ограничен
бюджетом и горизонтом 366 дней, необходимы подходящие сотрудники и оборудование.

## Документация

- docs/INTEGRATION.md — устройство интеграции, проверки и ограничения.
- docs/TEAM_DECISIONS.md — уточнения команды.
- docs/ui_api.md — интерфейс карты.
- db/proposals/ — предложение нормализованной схемы, пока не применяется.

Состояние сейчас хранится в api_state; SQL-миграции применяются отдельным
контейнером до запуска API. PostgreSQL сохраняет данные в именованном томе.
Не выполняйте docker compose down -v, если данные нужно сохранить.

Локальная форма создания заявок и дампы тестовой БД в репозиторий не входят.
